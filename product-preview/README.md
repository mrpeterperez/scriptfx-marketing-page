# ScriptFX product preview

The preview loads the application's existing root, project, and Write routes. It uses the same workspace shell, menu bar, editor, navigation, feedback panels, AI companion, status bar, fonts, and styles. The landing page supplies the existing Mac frame and Classic, With tools, and With AI controls. The screen is a guided visual demonstration, not an editable application session.

The embed never takes keyboard focus. A preview-only Lexical plugin types one continuous example using the actual screenplay nodes. Switching modes preserves that document and its typing position. Reduced motion shows the completed scene. Existing navigation and inspector panels stay mounted and resize with CSS transitions; the original spatial orb appears on the left for With AI. The service adapters are `data.js` and `presence.jsx`. They provide a disposable local project and one local writer. They do not contact Supabase, Liveblocks, or generation providers. The iframe is inert and does not accept document edits or account actions. Clicks on its surface receive visual feedback; the outer tabs and pause control drive the demonstration. The local data adapter supports the app renderer and its automatic state updates without external services.

Run `npm run build:product-preview` before `npm run build` after changing this preview or updating the app source. Set `SCRIPTFX_APP_ROOT` to the installed frontend checkout; its default is `/Users/peterperezjr/Documents/Clients/ScriptfXV1/scriptfxv1/frontend`. The public bundle is self-contained for normal landing builds. Its source manifest lists the imported app modules.

`screenplay-story.js` supplies The Last Night, an original demonstration draft with 127 populated scene pages. `data.js` maps its story moments into the application's existing nine-beat 3-Act (Syd Field) guide. Every scene has a stable identifier and belongs to exactly one beat. The preview uses the application's existing “start scene on a new page” setting to preserve the draft's page boundaries. The typing animation completes a line on page one without removing the rest of the screenplay. With tools opens the application's full-width Beats view with all scene assignments populated and the shared workspace header.

`recovery.js` replaces device-backup persistence only in the preview bundle. The demonstration neither reads nor writes the application's recovery database, so an interrupted typing animation cannot open a recovery dialog on reload. Existing device backups and the application's recovery behavior are unchanged.
